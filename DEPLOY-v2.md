# Развёртывание TG Parser v2.0 на Render (параллельно с v1)

> v2 разворачивается **рядом с работающим v1**, не трогая его. Изоляция: отдельный репозиторий (`tgparser_20`), отдельные Render-сервисы, отдельная БД, отдельная TG-сессия. Пульс продолжает читать v1, пока v2 не принят. План и критерии приёмки — ТЗ-tgparser-01 (раздел 10).

---

## Шаг 1. Отдельная TG-сессия для v2 (~5 минут, нужен телефон под рукой)

Два клиента на одной сессии выбивают друг друга, поэтому для v2 генерируем новую:

```bash
git clone https://github.com/vladfa2010/tgparser_20.git
cd tgparser_20
pip install telethon python-dotenv

export TG_API_ID=ваш_id        # тот же, что использует v1
export TG_API_HASH=ваш_hash
python generate_session.py     # ввести телефон и код из Telegram
```

Скопируйте длинную строку из вывода — это `TG_STRING_SESSION` для шага 3.

## Шаг 2. Создать стек v2 одним Blueprint'ом (~2 минуты)

1. [dashboard.render.com](https://dashboard.render.com) → **New +** → **Blueprint**.
2. Подключить репозиторий **`tgparser_20`** (если его нет в списке — *Configure account* → выдать доступ).
3. Render прочитает `render.yaml` и предложит создать три ресурса:
   - **tgparser-v2-db** — PostgreSQL (free, 1 ГБ, свежая — миграция данных из v1 не нужна);
   - **tgparser-v2-web** — дашборд + админка + RSS (starter);
   - **tgparser-v2-cron** — парсинг каждые 5 минут.
4. **Apply**. Первый билд образа (с torch для rubert) займёт 10–15 минут — это нормально.

## Шаг 3. Секреты

**tgparser-v2-cron → Environment → Add Environment Variable** (всё secret):

| Key | Value |
|---|---|
| `TG_API_ID` | ваш id |
| `TG_API_HASH` | ваш hash |
| `TG_STRING_SESSION` | строка из шага 1 |

**tgparser-v2-web → Environment:**

| Key | Value | Примечание |
|---|---|---|
| `ADMIN_PASSWORD` | надёжный пароль | secret, вручную — это пароль входа в `/admin` |
| `JWT_SECRET` | — | уже сгенерирован Blueprint'ом, трогать не нужно |

Если `ADMIN_PASSWORD` не задать — при первом запуске сгенерируется случайный и **один раз** напечатается в логе веб-сервиса.

## Шаг 4. Первый бэкфилл истории

1. **tgparser-v2-cron → Environment**: временно добавьте `HISTORY=1` → **Manual Deploy**.
2. Смотрите логи: канал `markettwits` засеется из `CHANNELS`, дальше — полная докачка истории (на большой объём уйдёт заметное время). Прерывать не страшно: upsert идемпотентен, докачка продолжится с места обрыва.
3. После успеха уберите `HISTORY=1` (или поставьте `0`) и задеплойте снова — дальше крон работает сам каждые 5 минут: новые посты + обновление просмотров/правок (окно 500 сообщений).

## Шаг 5. Проверка приёмки

| Проверка | Ожидаемо |
|---|---|
| `https://tgparser-v2-web.onrender.com/health` | `{"status":"ok","version":"2.0.0"}` |
| `https://…/onrender.com/` без логина | редирект на `/login` |
| вход в `/login` (admin + пароль из шага 3) | попадаете в `/admin` |
| `/admin` → каналы | `markettwits` активен, размечен «Новости», счётчик постов растёт; при ошибках парсиния виден текст напротив канала |
| `/rss/news`, `/rss/analytics` без логина | валидный RSS, `<title>` — «Новости» / «Аналитика» |
| `/rss/{username}` (напр. `/rss/markettwits`) | фид одного канала, `<title>` — название канала |
| `/rss/opml` без логина | OPML со всеми фидами — импортируется в Пульс одним файлом |
| v1 | работает как раньше, Пульс на нём и смотрит |

Регрессионный прогон smoke-теста локально (нужен PostgreSQL): см. `smoke`-сценарии в ТЗ-tgparser-01, раздел 7.

## Шаг 6. Переключение Пульса и вывод v1

1. Когда v2 стабильно поработал 3–5 дней (и v1 параллельно — без конфликтов сессий), в Пульсе замените URL фида на:
   - `https://tgparser-v2-web.onrender.com/rss/news`
   - `https://tgparser-v2-web.onrender.com/rss/analytics`
2. Наблюдайте пару дней. **Откат** = вернуть старые URL v1 (≤ 15 минут, ничего не пересобирая).
3. Через 2 недели стабильной работы v2: cron v1 — отключить (suspend), web v1 оставить до окончательного решения, затем удалить сервисы и БД v1.

## Управление каналами и потоками (после деплоя)

- Всё делается в **`/admin`**: добавить канал (он подхватится парсером на ближайшем прогоне, первичная докачка — 2000 последних постов), кнопка «Докачать всё» — полная история, разметка «Новости/Аналитика» — попадание в соответствующий фид, «выкл» — парсер игнорирует, посты сохраняются, «Удалить» — жёстко, посты выпадают из RSS.
- Названия фидов для Пульса меняются в админке (RSS-потоки) без редеплоя.
- Персональный фид канала: `/rss/{username}` — подписка в Пульсе на один канал.
- Все фиды разом: `/rss/opml` (импорт OPML в ридер), либо добавляйте URL по одному.
- Смена пароля админа в `/admin` мгновенно завершает все открытые сессии.

## Локальный запуск (docker compose)

```bash
cp .env.example .env   # прописать TG_API_ID/HASH, JWT_SECRET, ADMIN_PASSWORD
docker compose up postgres web
# веб на :10000, БД на :5432; парсер/планировщик — см. docker-compose.yml (profiles)
```
